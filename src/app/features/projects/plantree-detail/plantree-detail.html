Plantree

A household planning system that connects meals, grocery shopping, pantry management, and cooking into one continuous experience.

Overview

Plantree is a household planning system that connects meals, shopping, pantry management, and cooking into one continuous flow.

Instead of treating planning, grocery lists, and pantry tracking as separate tools, Plantree keeps them connected — helping households move naturally from deciding what to cook, to shopping, to using what is already available at home.

The product was shaped around everyday household routines, focusing on clarity, flexibility, and reducing friction around food organization and cooking decisions.

The home screen acts as the central entry point into the system, connecting planning, grocery lists, pantry management, meal suggestions, and household insights into a single workflow. The primary bottom navigation follows the core household flow from planning, to shopping, to pantry management.

A secondary navigation menu provides access to additional areas of the product, including Cook from Pantry, My Meals, Week Stats, notifications, language switching, household management, ingredient rules, spaces, account actions, and system settings. Space switching is also available directly from the top bar, allowing users to quickly move between different household contexts.

System

Plantree is built around a forward-flow structure that connects planning, shopping, pantry management, and meal suggestions into one evolving cycle.

Planned meals generate grocery lists, purchased products move into Pantry, and Pantry data is later reused to guide future cooking decisions and meal suggestions.

These transitions are intentionally designed to feel lightweight and connected, instead of behaving like isolated product areas.

Plantree also uses a shared member and space model. A single account can include multiple members, who can move across spaces, while each active space defines what is current and relevant — especially for pantry-based decisions and shared activity.

Recipes remain reusable across spaces, while pantry data stays tied to the active space. This keeps the system flexible for different home contexts without duplicating core meal data.

The system follows a few key principles:

  • One-direction flow
    Data moves forward through the system, avoiding circular dependencies and keeping the logic predictable.
  • Independent features
    Planning, lists, pantry, and suggestions can work on their own, while still benefiting from being connected.
  • Real-time collaboration
    Shared grocery lists update instantly between household members, supporting coordinated shopping without conflicts or manual refresh.
  • Smart matching
    Meal suggestions are based on what is available in the pantry, prioritizing recipes that best match current ingredients while still allowing flexibility.
  • Real-life alignment
    The structure mirrors how households actually operate — planning ahead, shopping, and then deciding what to cook based on what is available.
  • Evolving over time
    As more meals are added and ingredient data becomes richer, the system becomes more useful, improving suggestions and decision-making naturally.

Planning

Planning in Plantree is designed as a flexible system that supports both structured weekly organization and more dynamic, date-based decisions.

The weekly planning view provides an overview of the household schedule while still allowing quick adjustments at the day level. Past days become visually faded, helping users focus on the current and upcoming meals without losing the broader context of the week.

Past days are mostly locked to protect the historical plan, but small corrections remain possible. Users can still update the cook or meal status for past meals, allowing forgotten cooking activity to be reflected accurately in weekly statistics.

The home screen also provides a direct entry into the current day, opening the planning view focused on today's meals for quick access and adjustment.

Planning supports both lightweight scheduling and more detailed day-level organization. Multiple meals can be grouped within the same day, allowing households to plan different meals throughout the day while keeping the workflow simple and flexible.

Meals can be selected from an existing shared meal library or created directly during planning, reducing friction between meal creation and scheduling.

Search is available both in the planning flow and within the meal library, allowing users to quickly find meals by name or ingredients. Matching is intentionally flexible, so even imperfect queries can still surface relevant results.

Planning is directly connected to shopping. Meals added to the weekly plan can later be used to generate a grocery list, turning planned meals into a practical shopping workflow.

Planned meals also support a lightweight cooking lifecycle. Meals can move through preparation states such as To prepare, In progress, and Ready, helping households coordinate cooking activity throughout the week. These states are later reused by the household insights system.

  • Weekly overview with day-level control
    Users can navigate across the week while managing meals individually for each day.
  • Multiple meals per day
    Days can contain several planned meals, supporting more realistic household planning.
  • Flexible meal creation
    Meals can be reused from the shared library or created directly during the planning flow.
  • Integrated shopping transition
    Planned meals can later be transformed into grocery lists without duplicating work.
  • Multi-day meal assignment
    Meals from the library can be quickly scheduled across one or multiple dates.
  • Lightweight cooking coordination
    Meal preparation states help households coordinate what is currently being prepared, cooked, or already ready to serve.
  • Supports real-life adjustments
    Planning remains flexible and easy to change without disrupting the overall workflow.

Lists

Grocery Lists in Plantree support both manually created lists and lists generated directly from planned meals. Generated lists remain fully editable after creation, allowing users to freely adjust, add, remove, and organize items as needed.

Lists generated from the planning system act as snapshots of the selected meals at the time of creation. Future changes to meal plans do not automatically modify already created lists, allowing shopping workflows to remain stable once a household begins preparing or purchasing items.

Planning and shopping are directly connected. Users can generate grocery lists from upcoming meals and select specific days or meals during generation. Plantree automatically detects meals that are already covered by active lists or contain no ingredients.

Multiple entry points are supported throughout the flow. Lists can be created manually, generated from planned meals, reused from previous shopping sessions, and later adjusted with additional products or manual entries.

Generated lists still behave like regular editable lists. Users can manually add products, edit quantities, check off purchased items, remove entries, and continue adjusting the list at any time.

Plantree also supports ingredient normalization through customizable rules. Singular and plural ingredient names can be matched automatically, while measurement conversion rules allow recipe measurements such as cups, tablespoons, and teaspoons to be converted into normalized grocery quantities.

These remembered rules are automatically reused during future grocery generation. Compatible measurements are merged and summed together, reducing duplicate entries and producing cleaner shopping lists.

Recipe measurements and pantry inventory are intentionally treated as separate stages. Grocery lists normalize recipe language for shopping, while Pantry storage reflects what households actually purchased. During the Pantry transfer flow, users can adjust quantities, convert units, skip products, or store products using the quantities and package sizes that were actually purchased.

Lists support lightweight household coordination through real-time updates. Household members can immediately see changes, including who added or bought each list item, helping shopping stay synchronized across devices.

Active, completed, and archived list states help households organize shopping over time. Lists can also be pinned to keep important shopping workflows easily accessible.

  • Manual and generated workflows
    Lists can be created manually or generated directly from planned meals.
  • Snapshot-based generation
    Generated lists remain stable even if future meal plans later change.
  • Editable generated lists
    Generated lists remain fully editable after creation.
  • Ingredient normalization
    Singular/plural matching and measurement conversion rules reduce duplicate entries.
  • Persistent learning system
    Remembered rules are automatically reused during future grocery generation.
  • Real-time collaboration
    Changes appear instantly across household members and devices.
  • Pantry integration
    Bought products can be reviewed, adjusted, and transferred into Pantry inventory.
  • Flexible organization
    Lists support active, completed, archived, reused, and pinned states.

Pantry

Pantry in Plantree is designed as a flexible household inventory system that keeps track of products available at home while staying connected to shopping, planning, and cooking workflows.

Products can be added manually or moved directly from grocery lists after shopping, allowing Pantry to reflect real household purchases and stock over time.

The system supports both countable and measured products. Countable entries track product counts with optional size information, while measured entries support weight and volume-based quantities using standardized units such as g, kg, ml, and l.

Pantry management is intentionally flexible. Users can track quantities, optionally add package sizes, attach expiry dates, and organize products in ways that reflect real household shopping habits.

Pantry items can also be moved directly from grocery lists after shopping. During the move flow, users can review products, adjust quantities or package sizes, skip individual items, and decide how products should be stored before saving them to Pantry.

Ingredient matching is powered by a normalization and rule-based system shared across Pantry, Lists, and Cook From Pantry. Singular and plural forms can be remembered automatically, while compatible measurement units are normalized and converted when possible.

This allows recipe ingredients and shopping list entries to map more reliably to structured Pantry products, helping the system interpret real household inventory more accurately over time.

Pantry also powers the Cook From Pantry system, where meals are matched against available products and ranked based on ingredient availability and quantity sufficiency.

Matching remains intentionally forgiving. The system supports normalized names, remembered singular/plural rules, compatible unit conversion, and quantity-aware validation to surface meals that are realistically possible with the products currently available at home.

Users can inspect ingredient matches, review missing products, and immediately add suggested meals back into the planning flow for single or multiple days.

Cook From Pantry is accessible directly from Pantry, from the Home dashboard, and through secondary navigation, keeping Pantry-aware meal suggestions integrated into the broader planning workflow.

  • Flexible household inventory
    Pantry tracks real household products and quantities while staying connected to planning and shopping flows.
  • Countable and measured products
    Supports countable products with optional size information alongside standardized measured quantities.
  • Expiry and cleanup management
    Products can include expiry dates and can later be filtered or cleaned using dedicated cleanup flows.
  • Always-present products
    Common household staples such as salt, spices, or oil can be excluded from shopping generation while still participating in Pantry matching.
  • Shared ingredient intelligence
    Pantry reuses the same normalization, singular/plural recognition, and measurement conversion systems used across grocery lists and recipe matching.
  • Cook From Pantry suggestions
    Meals are ranked using ingredient availability and quantity-aware matching to help households identify meals that best fit their current Pantry contents.
  • Integrated planning workflow
    Pantry-based meal suggestions can immediately be added back into the weekly planning flow for one or multiple days.

Insights

Insights in Plantree provide a lightweight overview of household cooking activity throughout the week. The Week Stats screen highlights cooked meals, active cooks, household participation, and the Chef of the Week based on completed meals.

Meal status changes from the planning flow are reused here. When a planned meal is marked as ready, it becomes part of the weekly cooking history and contributes to household statistics.

Because past meals can still receive cook and status corrections, the statistics can reflect what actually happened even when users update the plan after the day has passed.

The feature highlights the Chef of the Week, total cooked meals, active cooks, a family leaderboard, and a feed of meals cooked during the week. This gives the household a simple way to see who contributed and what was prepared.

  • Cooking-based statistics
    Weekly stats are based on meals marked ready in the planning flow.
  • Chef of the Week
    The member with the most cooked meals is highlighted for the current week.
  • Household leaderboard
    Members are ranked by weekly cooking activity.
  • Cooked meals history
    The page shows which meals were cooked and who prepared them.
  • Lightweight motivation
    The feature adds feedback and recognition without turning the app into a strict tracking system.

Design

Plantree is designed around real household routines, with a focus on flexibility, clarity, and everyday usability. The interface focuses on lightweight interactions, flexible planning, and fast everyday actions that remain quick and easy to access during everyday household use.

The product follows a mobile-first approach, with quick-access navigation, sticky contextual controls, and flows optimized for frequent short interactions such as checking meals, updating shopping progress, or reviewing Pantry items while cooking or shopping.

Many interactions are intentionally progressive. Simple actions remain lightweight, while more advanced options appear only when needed. Examples include ingredient normalization review flows, Pantry adjustments, cleanup actions, and multi-day planning controls.

Visual consistency is maintained through reusable cards, chips, overlays, dialogs, and shared spacing systems. The interface uses soft surfaces, warm neutral backgrounds, and natural green accents to support the household and food-oriented identity of the product.

Responsiveness is treated as part of the product design rather than only a layout concern. Navigation, scrolling behavior, dialogs, sticky controls, and information density adapt across phone, tablet, and desktop environments while preserving the same workflow structure.

The system also prioritizes forgiving interactions. Users can freely adjust generated lists, correct previous cooking activity, normalize ingredient behavior over time, and move fluidly between planning, shopping, Pantry, and cooking workflows without losing context.

  • Mobile-first workflows
    Core interactions are optimized for fast, repeated household actions on mobile devices.
  • Progressive complexity
    Advanced controls appear only when needed, keeping common actions lightweight.
  • Responsive interaction patterns
    Navigation and interaction models adapt across mobile, tablet, and desktop layouts.
  • Reusable visual system
    Shared cards, chips, dialogs, overlays, and spacing rules maintain visual consistency.
  • Forgiving user experience
    Users can adjust workflows over time instead of being locked into rigid system behavior.

Tech

Plantree is built as a responsive Angular-based Progressive Web App focused on real-time household planning and smooth mobile-first interactions. The application combines structured meal planning, grocery workflows, pantry management, and reusable ingredient logic inside a single shared system.

The frontend is built with standalone Angular components and SCSS, using a shared design system with reusable layouts, chips, dialogs, cards, bottom sheets, and responsive breakpoints across mobile, tablet, and desktop devices.

Supabase powers authentication, realtime synchronization, database storage, and image uploads. Realtime subscriptions keep shared household data synchronized across devices, supporting collaborative planning, grocery management, and pantry workflows.

Ingredient processing is handled through custom parsing and normalization utilities that support:

  • Singular and plural recognition for ingredient matching and automatic merging.
  • Measurement normalization between compatible units such as g / kg and ml / l.
  • Reusable ingredient rules for remembered conversions and naming patterns.
  • Flexible pantry quantities that preserve what was actually purchased rather than forcing recipe-specific measurements.

The project also includes multilingual support with dynamic English and Bulgarian translations, member-specific language preferences, realtime household state management, reusable calendar systems, responsive overlays, and shared interaction patterns across all major flows.
